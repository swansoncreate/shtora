# Shtora

Shtora — симулятор социальной жизни персонажа: Instagram-подобная лента, профиль, Stories, Highlights, личные сообщения, Dropbox, Imagine и настройки.

> **Текущий статус:** проект находится в активной разработке. Публикуемый Grok Build и VPS-интеграция проверяются отдельно; рабочие изменения сначала проходят тестовую ветку.

## Что умеет приложение

Главная идея Shtora — не набор отдельных генераторов, а **единый мир персонажа**, в котором Instagram, переписка и фотографии используют общее состояние.

### Основные разделы

| Раздел | Назначение |
|---|---|
| **Instagram** | Лента, профиль, публикации, Stories и Highlights |
| **DM** | Живой диалог с персонажем внутри Instagram |
| **Dropbox** | Источник фотографий и визуальных материалов |
| **Imagine** | Генерация и продолжение фотографий |
| **Settings** | Настройки приложения |

### Общая схема

~~~text
                         ┌─────────────────┐
                         │     Instagram   │

                         │ stories / posts │
~~~

## 1. Instagram

Instagram является основным визуальным входом в приложение.

Пользователь работает с привычными сущностями:

- лента;
- профиль;
- публикации;
- Stories;
- Highlights;
- переход в личные сообщения.

Фотография не существует отдельно от персонажа: сохранённые визуальные данные могут использоваться дальше в диалоге и при создании новых кадров.

### Схема интерфейса

~~~text
┌─────────────────────────────────────────────┐
│ Instagram                                   │
├─────────────────────────────────────────────┤
│ Stories  ○ ○ ○ ○ ○ ○                       │
├─────────────────────────────────────────────┤
│                                             │
│              POST / PHOTO                   │
│                                             │
│              caption / time                 │
│                                             │
├─────────────────────────────────────────────┤
│  Home        Search       +       Profile   │
└─────────────────────────────────────────────┘
~~~

> Иллюстрация выше — схема интерфейса по архитектуре проекта, а не скриншот production UI.

## 2. Личные сообщения (DM)

DM — основной способ взаимодействия с персонажем.

Обычное сообщение обрабатывается как разговор и **не должно автоматически запускать генерацию изображения**.

Когда пользователь просит фотографию, система сначала определяет намерение.

Примеры:

- «сделай селфи» → continue;
- «покажи себя боком» → continue + side;
- «сфотографируй со спины» → continue + back;
- «во весь рост» → continue + full;
- «я хочу увидеть, где ты сейчас» → pov;
- «давай в кафе, в другой одежде» → new_scene;
- запрос фотографии из прошлого → memory.

~~~text
Пользователь
     │
     ▼
   DM / Chat
     │
     ├── обычная реплика ─────────► ответ персонажа
     │
     └── фото-намерение
              │
              ▼
        Photo Intent
              │
       ┌──────┼─────────┐
       ▼      ▼         ▼
    CONTINUE NEW_SCENE  POV
       │      │         │
       └──────┴─────────┘
              │
              ▼
        Generation Job
~~~

## 3. Фотографии и визуальная непрерывность

Ключевой принцип Shtora:

> **Фотографии — наблюдения одного непрерывного мира, а не независимые генерации.**

Для каждого визуального кадра сохраняются:

- место;
- одежда;
- активность;
- сцена;
- камера;
- parent кадра;
- источник;
- prompt;
- snapshot мира.

~~~text
frame-1
  scene-1 / room / selfie
       │
       ▼
frame-2
  scene-1 / room / back
       │
       ▼
frame-3
  scene-2 / cafe / full
~~~

Поэтому запрос «теперь покажись со спины» продолжает текущую сцену, а запрос «поехали в кафе» создаёт новую.

## 4. Камеры и режимы

Поддерживаются визуальные режимы:

- selfie
- mirror
- side
- back
- full
- pov
- candid
- gallery

~~~text
              SAME SCENE
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      selfie     side      back
        │         │         │
        └─────────┼─────────┘
                  ▼
             same sceneId
~~~

Это позволяет менять точку съёмки, не ломая состояние сцены.

## 5. Новая сцена

Явное изменение места или одежды создаёт новую сцену.

**Было**

~~~text
scene-1
place: room
clothes: casual
camera: selfie
~~~

**Пользователь пишет:** «Давай в кафе, надень чёрную куртку и сфотографируйся во весь рост».

**Становится**

~~~text
scene-2
place: cafe
clothes: black jacket
camera: full
parentSceneId: scene-1
~~~

При этом визуальная память предыдущей сцены не удаляется.

## 6. Visual Memory

Каждый важный визуальный результат может попасть в долговременную визуальную память.

Запоминаются:

- изображение;
- сцена;
- камера;
- parentId;
- sceneId;
- теги;
- prompt;
- snapshot состояния мира;
- источник фотографии.

~~~text
VisualMemory
├── imageUrl
├── scene
│   ├── place
│   ├── clothes
│   ├── activity
│   └── sceneId
├── camera
├── source
├── parentId
├── tags
└── worldSnapshot
~~~

## 7. Dropbox

Dropbox используется как источник фотографий.

При выборе исходного изображения система:

1. получает изображения из выбранной папки;
2. предпочитает подходящие фотографии с лицом;
3. исключает очевидные cover/video-файлы;
4. может перемешивать выбор;
5. сохраняет историю использованных source paths.

История источников нужна, чтобы одна и та же фотография не использовалась подряд без необходимости.

## 8. Imagine

Imagine отвечает за визуальную генерацию/редактирование.

Generation Job проходит жизненный цикл:

~~~text
queued
  │
  ▼
planning
  │
  ▼
source_selected
  │
  ▼
generating
  │
  ├──────────────► failed
  │                   │
  │                   ▼
  │                 queued
  │
  ▼
persisted
~~~

В job сохраняется контекст, необходимый для retry:

- intent;
- sceneId;
- parentId;
- provider;
- source;
- final prompt;
- world snapshot;
- ошибка и retryable-флаг.

Поэтому сбой провайдера не должен уничтожать историю сцены.

## 9. Состояние мира

Помимо Visual Memory приложение хранит отдельный **World State**.

Он содержит, например:

- место;
- активность;
- одежду;
- настроение;
- доступность;
- присутствующих;
- sceneId.

World State сохраняется на диск и восстанавливается после перезапуска процесса.

~~~text
World State
────────────
place     = cafe
activity  = lunch
clothes   = black jacket
sceneId   = scene-2
~~~

Это важно: после рестарта персонаж не должен «забыть», где он находится и в какой сцене была сделана последняя фотография.

## 10. Обычный разговор не вызывает Imagine

Архитектурно чат и генерация разделены.

~~~text
"Как прошёл день?"
        │
        ▼
     Chat Engine
        │
        ▼
   текстовый ответ

"Сделай фото со спины"
        │
        ▼
   Photo Intent
        │
        ▼
 Generation Job
        │
        ▼
     Imagine
~~~

Это защищает от случайных генераций и лишних обращений к image provider.

## 11. Grok Build / VPS

В тестовой конфигурации VPS может передавать операции опубликованному Grok Build:

~~~text
Shtora VPS
    │
    │ X-Shtora-Key
    ▼
Published Grok Build
    │
    ├── reply
    ├── ping
    └── imagine
~~~

Локальный runtime при этом может использовать прямой xAI API для Imagine.

Маршрутизация выбирается runtime-конфигурацией, а не самим пользовательским сообщением.

## 12. Надёжность и восстановление

Для файлового состояния используются атомарные записи и очереди по пользователю.

Проверяется восстановление после полного перезапуска процесса:

- Visual Memory;
- Generation Jobs;
- Dropbox source history;
- World State;
- sceneId;
- одежда и место.

Неизвестный Generation Job не должен создаваться или изменять существующий список при попытке update.

## 14. Тестирование

Основные автоматические проверки покрывают:

- visual intent;
- continuity;
- scene transitions;
- POV;
- malformed semantic output;
- Visual Memory persistence;
- Generation Job persistence;
- retry;
- source history;
- unknown job updates;
- World State persistence;
- восстановление после restart;
- контракт Grok reply/ping/imagine.

Перед изменением main тестовая ветка должна пройти полный цикл проверки.

## Важное замечание о «скриншотах»

README намеренно содержит **архитектурные иллюстрации**, построенные по реальному коду проекта, а не выдуманные изображения интерфейса.

Когда появятся реальные screenshots UI, их можно добавить в разделы Instagram, DM, Imagine и Dropbox без изменения описанной архитектуры.

## Структура концепции

~~~text
                    SHTORA
                       │
          ┌────────────┼────────────┐
          │            │            │
      Instagram       DM        Dropbox
          │            │            │
          │            ▼            │
          │      Photo Intent       │
          │            │            │
          └────────────┼────────────┘
                       ▼
                 Visual World
                       │
              ┌────────┴────────┐
              ▼                 ▼
        Generation Jobs    Visual Memory
              │                 │
              ▼                 ▼
            Imagine         Feed / DM
~~~

Shtora таким образом связывает **социальный интерфейс, разговор, состояние мира и визуальную память** в одну систему, а не рассматривает фотографию как отдельный одноразовый запрос.
